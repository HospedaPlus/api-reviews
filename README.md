# api-reviews — HospedaPlus F5 (Guest Reviews API)

Simulated **F5 source** of the *HospedaPlus Revenue* project: a paginated REST API that
publishes guest reviews from several platforms (Booking, Google, Tripadvisor, Expedia) in
**Spanish, English and Portuguese**, about **~300 reviews per day** for the 28 hotels of the chain.

The data platform ingests it daily to compute the **reputation score (RN-10)** and to feed the
Power BI reputation page. Reviews are synthetic (the brief forbids scraping real platforms) and
are generated by a **versioned, reproducible seed**.

| | |
|---|---|
| Stack | Python 3.12 · FastAPI · SQLModel · Alembic · PostgreSQL 16 · uv |
| Docs | `http://localhost:8000/docs` (Swagger) · `/openapi.json` |
| Image | Multi-stage, non-root, runs migrations on start |

## Quick start (one command)

Requirements: Docker with Compose v2.

```bash
docker compose up --build
```

This will:

1. Start PostgreSQL 16 with a persistent volume and wait for its health check.
2. Build the API image, apply the Alembic migrations and start FastAPI on port **8000**.
3. Run the **seed** once (dev mode: 30 days × ~20 reviews/day) when the API is healthy.

Then open <http://localhost:8000/docs>.

No `.env` is needed: defaults live in `docker-compose.yml`. To change them, copy
`.env.example` to `.env`. Postgres is published on host port **5433** to avoid clashing with
other local projects.

```bash
docker compose logs -f api                       # API logs
docker compose run --rm seed python -m src.seed --mode full   # ~115k reviews (~1 year)
docker compose down                              # stop (keeps data)
docker compose down -v                           # stop and delete the database
docker compose exec db psql -U postgres -d reviews
```

### Without Docker (development)

```bash
uv sync                                  # install deps (incl. dev tools)
cp .env.example .env                     # DATABASE_URL -> Postgres on localhost:5433
docker compose up -d db                  # only the database
uv run alembic upgrade head
uv run python -m src.seed
uv run fastapi dev src/main.py
```

## API

Base path: `/api/v1`. All timestamps are **UTC** (ISO 8601).

| Method | Path | Description | Codes |
|---|---|---|---|
| GET | `/health` | Liveness (ALB / ECS health check) | 200 |
| GET | `/health/ready` | Readiness (checks the database) | 200, 503 |
| GET | `/api/v1/hotels` | Hotel catalog (28 hotels) | 200 |
| GET | `/api/v1/reviews` | **Paginated** list with filters | 200, 422 |
| GET | `/api/v1/reviews/{id}` | Review by id | 200, 404 |
| POST | `/api/v1/reviews` | Create a review | 201, 409, 422 |
| PATCH | `/api/v1/reviews/{id}` | Partial update (rating, title, text, language) | 200, 404, 422 |
| DELETE | `/api/v1/reviews/{id}` | Delete | 204, 404 |

### Pagination and filters

`GET /api/v1/reviews?page=1&page_size=50&hotel_id=HP-CO-001&published_from=2026-09-01&published_to=2026-09-01`

| Param | Type | Notes |
|---|---|---|
| `page` | int ≥ 1 | default 1 |
| `page_size` | 1–100 | default 50 |
| `hotel_id` | string | e.g. `HP-CO-001` (see `/api/v1/hotels`) |
| `platform` | `booking` \| `google` \| `tripadvisor` \| `expedia` | |
| `language` | `es` \| `en` \| `pt` | |
| `min_rating`, `max_rating` | 1–5 | |
| `published_from`, `published_to` | date | inclusive, UTC |
| `order` | `asc` \| `desc` | by `published_at`, then `id` (stable pages) |

```json
{
  "items": [
    {
      "id": 355,
      "external_id": "GG-e0de4b967aad530c",
      "platform": "google",
      "hotel_id": "HP-CO-001",
      "language": "es",
      "rating": 3,
      "title": "Podría mejorar",
      "text": "Estadía correcta. La habitación no estaba limpia al llegar.",
      "reviewer_name": "Valentina Hernández",
      "reviewer_country": "PE",
      "stay_date": "2026-08-31",
      "published_at": "2026-09-18T10:32:58Z",
      "created_at": "2026-09-18T10:32:58Z",
      "updated_at": "2026-09-18T10:32:58Z"
    }
  ],
  "pagination": {
    "page": 1, "page_size": 50, "total_items": 7, "total_pages": 1,
    "has_next": false, "has_previous": false
  }
}
```

**Daily ingestion pattern:** call with `published_from` = `published_to` = the day to load and
follow the pages while `has_next` is `true`.

Errors raised by business rules share one shape:

```json
{ "error": "not_found", "detail": "Review 99999 not found" }
```

Request validation errors use FastAPI's standard `422` body.

> **PII notice (RN-11):** `reviewer_name` is personal data. This source returns it as the
> platforms would; the ingestion layer must **pseudonymize** it before it reaches the
> analytical layer.

## Seed (simulated data)

```bash
python -m src.seed --help
```

| Option | Env var | Default | Description |
|---|---|---|---|
| `--mode dev\|full` | `SEED_MODE` | `dev` | dev: 30 days × 20/day · full: 365 days × 300/day |
| `--seed` | `SEED_VALUE` | `42` | Fixed seed → reproducible data |
| `--end-date` | `SEED_END_DATE` | `2026-09-30` | Last day generated (fixed so reruns match) |
| `--start-date` | `SEED_START_DATE` | end − mode days | |
| `--date` | — | — | Generate a **single day** (daily batch) |
| `--reviews-per-day` | `SEED_REVIEWS_PER_DAY` | per mode | ±15 % daily variation |
| `--duplicate-rate` | `SEED_DUPLICATE_RATE` | `0.05` | Share of reviews also posted on another platform |
| `--dry-run` | — | — | Generate without writing |

How it meets the brief (§5.2):

1. **Fixed seed** — each day uses its own RNG seeded with `"<seed>:<date>"`.
2. **Idempotent** — rows are inserted with `ON CONFLICT (platform, external_id) DO NOTHING`;
   running it twice inserts nothing the second time.
3. **Parametrized volume** — `dev` / `full` modes and `--reviews-per-day`.
4. **Referential integrity** — hotels come from the shared catalog `src/catalog/hotels.json`.
5. **Configurable defects** — `--duplicate-rate` injects the same review on a second platform
   with a slightly different guest name (accents removed, lower/upper case, initial) and an
   earlier publication time. Downstream deduplication must detect them.
6. **Local and AWS** — it only needs `DATABASE_URL`; in AWS it runs as a one-off ECS task.

A day always produces the same reviews regardless of the requested range, so a daily job
(`--date $(date -u +%F)`) and a full backfill never disagree. A full run (~115k rows) takes
about 40 s against a local Postgres.

### Hotel catalog

`src/catalog/hotels.json` holds the 28 hotels (code, city, country, **timezone**, type, rooms).
`HP-PT-001` and `HP-PT-002` are the two Portuguese hotels of the Kaggle history (F1). Other
sources (F2 channel manager, F3 booking engine, F4 agencies) should reuse these codes.

## Project structure

```
src/
├── main.py                  # FastAPI app, routers, error handlers, request logging
├── api/
│   ├── routers/             # HTTP layer: health, hotels, reviews
│   ├── dependencies.py      # DI: session -> repository -> service
│   └── errors.py            # Domain errors -> HTTP responses
├── services/                # Business rules (validation, pagination, conflicts)
├── repositories/            # Data access only (SQLModel queries)
├── schemas/                 # Request/response contracts (Pydantic)
├── models/                  # SQLModel tables
├── core/                    # Settings, hotel catalog, domain errors
├── shared/database/         # Engine and session dependency
├── catalog/hotels.json      # Shared hotel catalog
└── seed/                    # Deterministic data generator + CLI
alembic/                     # Migrations
tests/                       # API and seed tests (SQLite by default, Postgres in CI)
```

Layering keeps HTTP concerns (routers), business rules (services) and SQL (repositories)
apart, so each layer can be tested and changed on its own.
